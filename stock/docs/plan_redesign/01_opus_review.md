## 0. 바뀐 결정 (요약)

1. **저울 물가 = 계획 물가(plan.inflation) 하나만 쓴다.** scale에 inflation을 따로 두지 않는다. 물가 값이 두 군데 있으면 어느 쪽이 맞는지 헷갈린다.
2. **②의 목표는 언제나 '통장 숫자'이고 고정된 값이다.** 숨은 연결 모드는 만들지 않는다. 저울에서 가져왔다는 사실만 `fromScale`에 남겨, '기간' 질문과 '기간을 바꿨을 때' 안내 한 줄에만 쓴다.
3. **'기간' 질문에서 저울 목표의 함정을 막는다.** 20년 기준 목표(1억 6,386만원)를 12년 안에 채우면 오늘 돈 가치로는 1억 2,184만원어치를 모은 셈이다. 그래서 "오늘 돈 1억 가치를 지키려면 9년 5개월" 줄을 함께 보여 준다.
4. **처음 열 때 기본 질문은 '매달 넣을 돈'이다.** 초안의 '기간'으로 시작하면 이미 정해 둔 goalYears가 '?' 칸이 되어 사라진다.
5. **예전 계획의 수익률은 '첫 구간'이 아니라 '같은 결과를 내는 한 가지 수익률'로 채운다.** 기본 계획(3→5→7%, 15년)에서 첫 구간 값은 3%, 단순 평균은 5.27%, 같은 결과를 내는 수익률은 5.7%다.
6. **goalBasis='today'인 계획은 goalAmount를 그해 숫자로 바꿔 저장한다.** 10억, 20년, 물가 2.5%면 16억 3,862만원이 된다. 최근 5회 기록을 되돌릴 때도 같은 변환을 해야 한다(빠뜨리면 목표가 몰래 바뀐다).
7. **결과 구역 KPI에서 역산 3개(필요한 월 납입·한 번에 넣는다면·필요한 수익률)를 뺀다.** ②와 같은 질문인데 구간 수익률로 계산해서 숫자가 달라 보인다. 정확한 역산은 기존 '대안' 칩(점선 미리보기)이 맡는다.
8. **필요한 금액·수익률은 화면에 보이기 전에 올림한다.** 금액은 10만원 이상이면 1만원 단위, 그보다 작으면 1천원 단위로, 수익률은 0.1%p 단위로 올린다. `fmtKRW`는 반올림이라 보이는 값대로 넣으면 목표에 조금 모자랄 수 있다.
9. **노후 자금 모드에서는 ②의 목표가 '은퇴 때 필요 자금'을 따라간다(link='plan').** 직접 고치면 연결이 풀리고 "다시 가져오기"가 나온다. 기간 답을 반영하면 은퇴 나이가 바뀐다.
10. **국밥 막대 자리에는 "= 오늘 돈으로 X어치" 한 줄과 [저울에 올려 보기] 버튼을 둔다.** 국밥 예시는 저울의 '?' 도움말 안으로 옮긴다.

## 1. 초안에서 고칠 점

### 1-1. 구조: ① 저울과 ② 실행 목표의 관계

| 초안 | 문제 | 고칠 안 |
|---|---|---|
| 저울에 `inflation`을 따로 저장 | 계획 입력의 '물가상승률'과 값이 두 개가 된다. 은퇴 필요 자금은 plan.inflation으로 계산한다. | 저울의 물가칸은 plan.inflation을 그대로 고친다. 아래 '자세한 계획'의 물가칸과 같은 값이다. scale에는 `{today, then, years, last}`만 둔다. |
| '이 금액을 목표로' → ②의 목표와 기간을 채움 | ②가 '기간' 질문이면 기간은 '?' 칸이다. 20년 기준 금액을 넣고 답이 12년으로 나오면, 그해 숫자의 '그해'가 맞지 않는다. | 목표 칸 라벨에서 연도를 빼고 "목표 금액(통장 숫자)"로 쓴다. 저울에서 가져왔으면 `fromScale={today, years}`를 남기고, 기간 답 아래에 실질 목표로 구한 답을 한 줄 더 보여 준다(2-1). |
| ②에서 기간만 바꿈(목표는 저울의 20년 기준 그대로) | 목표의 '그해'가 기간과 어긋난다. | 안내 한 줄과 버튼을 둔다(스위치는 아님): "저울에서 가져온 목표는 2046년 기준이에요. [목표도 15년에 맞추기 → 1억 4,483만원]" |
| 두 카드가 '자세한 계획'과 따로 놂 | ②의 값과 아래 계획이 어긋나도 알 길이 없다. | ②의 입력값(목표·기간·목돈·매달·수익률)이 아래 계획과 다르면 작은 표시 "아래 계획과 달라요"와 [아래 계획에서 가져오기]를 보여 준다. |
| 국밥 막대를 없애기만 함 | 결과 숫자와 저울을 잇는 길이 없어진다. | 결과의 hero 아래에 "= 오늘 돈으로 X어치" 한 줄과 [저울에 올려 보기]를 둔다. 누르면 scale이 `{then: 예상 자산, years, last:'then'}`이 되고 화면이 위로 올라간다. |

### 1-2. 노후 자금 모드에서의 쓰임

- ②의 목표에는 `res.lp.needAtRetire`를 원 단위로 반올림해 넣는다. 만원 단위로 올리면 저울의 오늘 돈이 4억 3,186만원이 아니라 4억 3,187만원이 되어 결과 KPI와 1만원 어긋난다.
- 기간은 `retireAge − age`년이다. 기본 계획이면 은퇴 때 필요 자금 6억 2,546만원(오늘 돈 4억 3,186만원), 기간 15년이다.
- 목표는 연결 상태(`calc.link='plan'`)로 둔다. 생활비·연금·은퇴 나이를 바꾸면 ②의 목표도 따라 바뀐다. 목표를 직접 고치면 `link=null`이 되고 [다시 가져오기]가 나온다.
- ②의 계산은 은퇴 전까지 같은 금액을 넣는다고 본다. 그래서 다음 경우에는 안내 한 줄을 띄운다: saveUntilAge < retireAge, monthlyGrowth > 0, 은퇴 전 목돈(events)이 있을 때.
- '이 값으로 아래 계획 바꾸기'를 노후 자금 모드에서 누르면 이렇게 넣는다.
  - 기간 → retireAge = age + ⌈n/12⌉ (안내: "은퇴 나이를 바꾸면 필요 자금도 다시 계산돼요")
  - 매달 → monthly
  - 처음 목돈 → initial
  - 수익률 → accSegs를 한 구간으로
  - 목표(필요 자금)는 계산해서 나오는 값이라 넣지 않는다.
- 목표 금액 모으기 모드에서는 이렇게 넣는다: goalAmount=target, goalYears(기간 답이면 ⌈n/12⌉, 예: 12년 4개월 → "넉넉하게 13년으로 넣었어요"), initial, monthly, 수익률 → accSegs=[{from:1,to:null,rate}].
- 수익률을 반영하면 구간이 여러 개였던 계획은 구간이 하나로 합쳐진다. 그래서 반영 뒤에는 늘 [되돌리기] 토스트를 띄운다.

### 1-4. 계산 규칙 보완

- **i = 0일 때의 식이 빠졌다.** 매달 C = (T − P0)/n, 처음 목돈 P0 = T − C·n이다.
- **n = 0을 따로 막아야 한다.** 매달 질문은 0으로 나누게 된다 → "기간을 1년 이상 넣어 주세요." 처음 목돈 질문은 P0 = T로 답해도 된다. 수익률 질문은 P0 ≥ T가 아니면 답이 없다.
- **보이는 값은 올림한다(결정 8).** 수익률은 이분법으로 1e−6까지 좁힌 뒤 0.1%p 단위로 올린다(−2.47%는 −2.4%가 된다). '넣은 돈 / 불어난 돈' 막대와 "모여요" 문장은 올림한 값으로 다시 계산한 FV를 쓴다. 그래야 숫자가 서로 맞는다.
- **수익률 이분법의 범위는 −50% ~ 100%다.** 엔진의 `requiredRate`는 아래 끝이 −99%로 정해져 있다. `lo` 옵션을 더하자(기본값은 그대로 두어 기존 96개 테스트에 영향이 없게).
- **'처음 목돈' 질문에는 엔진 함수가 없다.** `requiredInitial(inp, target)`을 새로 만든다: fv0 = FV(초기 0), g = FV(초기 1, 적립 0) → (T − fv0)/g. calc/check.mjs 초안과 같은 식이다.
- **기간 탐색은 `requiredMonths`(최대 1200개월)를 그대로 쓴다.** 실질 목표 줄(결정 3)은 `targetIsReal:true`를 쓴다. 이때 물가는 (1+π)^(n/12)로 반영되어 엔진과 같다. 저울만 정수 년수를 쓴다.
- **'다른 길'을 고르는 규칙이 없었다 → 아래처럼 정한다.**
  - 매달 늘리는 폭: C < 100만원이면 +10만원, C < 500만원이면 +50만원, 그 이상이면 +100만원. C = 0이면 10만원으로 본다.
  - 수익률: +2%p. 단, 올린 값이 15% 이하일 때만 보여 준다.
  - 기간: +5년.
  - '현실적인 수익률' 기준값은 연 7%다. 새 목표 계획의 기본값과 같다. 출처를 단 주장은 하지 않는다.
  - 대안이 0원 이하가 되면 "없이도 돼요"로 쓴다.
- **'넣은 돈 / 불어난 돈' 막대 색:** 불어난 돈이 양수면 --up 계열, 음수면 --down 계열로 칠하고 라벨을 "줄어든 돈"으로 바꾼다(한국식).

### 1-5. 문구

- "반영" → **"이 값으로 아래 계획 바꾸기"**("반영"은 쉬운 말이 아니다).
- 질문 칩의 "기간 / 매달 넣을 돈 / 처음 목돈 / 수익률" → **"걸리는 기간 / 매달 넣을 돈 / 처음 목돈 / 필요한 수익률"**. 무엇을 구하는지가 칩 글자에 드러나게 한다.
- 초안의 답 "12년 (2038년 11월)"은 맞다(144개월, 오늘 2026년 11월 기준). 형식은 `fmtSpan(n)` + "(YYYY년 M월)"이다. 달은 이번 달에서 n개월 뒤로 센다.
- "현실적으로 어려움" → 상태 알약 **"! 높은 수익률"** + 문장 "연 15%가 넘는 수익률을 오래 내기는 어려워요."
- 결과 숫자는 fmtKRW로 쓴다(앞 두 단위, 만원 반올림). 입력칸 옆 한글 읽기는 `data-money`만 붙이면 moneyHints가 처리하고, '천' 규칙도 자동으로 따른다. 마이너스는 fmtPct가 쓰는 U+2212다.

## 2. ② 실행 목표 만들기 — 질문별 명세

### 공통

- 카드 제목: **실행 목표 만들기**
- 질문 줄: **무엇이 궁금해요?** `[걸리는 기간] [매달 넣을 돈] [처음 목돈] [필요한 수익률]` (.seg, aria-pressed)
- 입력칸 다섯 개. 고른 질문의 칸은 `?` 결과칸(output)이 된다.
  - **목표 금액** `[ ]원` — 캡션 "(통장 숫자)". 노후 모드 라벨은 "은퇴 때 필요 자금"이고, 캡션은 "자세한 계획에서 계산 · {2041}년 통장 숫자 · 고치면 연결이 풀려요"다.
  - **지금 목돈** `[ ]원` + 링크 [내 자산에서]
  - **매달 넣을 돈** `[ ]원`
  - **연수익률** `[ ]%` (소수 한 자리, −50 ~ 100)
  - **기간** `[ ]년` (정수 0 ~ 100). 노후 모드 라벨은 "은퇴까지"이고 캡션은 "({60}세)"다.
- 계산 방식 캡션(늘 보임): "수익률 한 가지 · 매달 같은 금액 · 월말에 넣는다고 보고 계산해요."
- 조건부 캡션: "아래 계획의 목돈 {N}건 · 적립액 매년 {g}% 증가는 넣지 않았어요." / "적립을 {55}세에 멈추는 설정은 넣지 않았어요."
- 버튼: **[이 값으로 아래 계획 바꾸기]** **[연 {r}% 내는 투자 규칙 찾기 →]**
- 반영 뒤 토스트: "아래 계획을 바꿨어요." + [되돌리기]
- 계획과 다를 때: 작은 표시 "아래 계획과 달라요" + [아래 계획에서 가져오기]
- 입력 오류(결과 자리에 회색 글자로)
  - 목표 ≤ 0: "목표 금액을 넣어 주세요."
  - 기간 > 100: "기간은 100년까지 넣을 수 있어요."
  - 수익률 범위 밖: "수익률은 −50%에서 100% 사이로 넣어 주세요."
  - 금액 < 0: "0원 이상으로 넣어 주세요."
- 결과 막대: `넣은 돈 {X} | 불어난 돈 {Y}`. 음수면 `줄어든 돈 {−Y}`(--down).
- 결과 문장의 금액은 fmtKRW, 기간은 fmtSpan, 연도는 오늘에서 n개월 뒤다.

### 2-1. 걸리는 기간 (ask='years')

입력: 목표, 지금 목돈, 매달, 수익률.

| 경우 | 결과 문장(화면 문구) |
|---|---|
| 닿음 | 큰 글자 **"{12년} 걸려요"** + 작은 글자 "({2038년 11월})"<br>"그때 통장에 {1억 6,434만원}이 모여 목표 {1억 6,386만원}을 넘어요. 이 목표는 {2038}년엔 오늘 돈 {1억 2,184만원}어치예요." |
| 저울에서 가져온 목표(fromScale 있음) | 한 줄 더: "오늘 돈 {1억원} 가치를 지키려면(물가만큼 목표도 키우면) **{9년 5개월}**({2036년 4월}) · 그때 목표 {1억 2,618만원}" [이 목표로 바꾸기] |
| 이미 넘음(n=0, 목표 ≤ 지금 목돈) | **"지금 바로 닿아요"**<br>"지금 목돈 {6,000만원}이 목표 {5,000만원}보다 {1,000만원} 많아요." |
| 100년 안에 못 닿음 | **"100년 안에는 닿지 않아요"**<br>"100년 뒤에도 {1억 2,000만원}이에요." (수익률이 음수면 "수익률이 마이너스라 돈이 {1억 1,722만원} 근처에서 더 늘지 않아요."를 더한다. 극한값은 C/\|i\|) |
| 못 닿을 때 대안 2개 | 기준 기간 H = fromScale.years, 없으면 계획 기간, 그것도 없으면 20년.<br>① "{20}년 안에 닿으려면 매달 **{417만원}**" [이걸로]<br>② "{20}년 안에 닿으려면 처음 목돈 **{9억 7,600만원}**" [이걸로]<br>(필요한 수익률이 15% 이하이면 ②를 "연 {x}% 수익률이면"으로 바꾼다) |
| 닿을 때 '다른 길' 2개 | "매달 {60만원}이면 {10년 10개월}" · "연 {8.0}%면 {10년 6개월}" (1-4의 규칙) |

경계:
- 수익률 0% → 선형으로 계산한다(1억, 매달 50만원 → 200개월 = 16년 8개월).
- 음수 수익률 → 닿을 수도 있다(−5%, 5,000만원 + 50만원 → 26년 7개월). 못 닿으면 위 문구.
- 매달 0원이고 수익률 ≤ 0%이며 목돈 < 목표 → 못 닿음.
- 기간 칸은 '?'라 기간 관련 경계는 없다.

### 2-2. 매달 넣을 돈 (ask='monthly')

입력: 목표, 지금 목돈, 수익률, 기간.

| 경우 | 결과 문장 |
|---|---|
| 필요 | 큰 글자 **"매달 {150만원}씩 넣으면 돼요"**<br>"{20}년 뒤({2046년 11월}) {10억 87만원}이 모여 목표 {10억원}을 넘어요." (+ 계획에 월 적립이 있으면 "지금 계획(월 {100만원})보다 {50만원} 더예요.") |
| 필요 없음(C ≤ 0) | **"매달 넣지 않아도 돼요"**<br>"지금 목돈 {8,000만원}이 {5}년 뒤 {1억 706만원}으로 불어나 목표 {1억원}을 넘어요." [매달 0원으로 바꾸기] |
| 기간 0 | "기간을 1년 이상 넣어 주세요." |
| 대안 2개(늘 보임, "부담을 줄이는 길") | ① "기간을 {25}년으로 늘리면 매달 **{85만원}**" ② "수익률이 연 {8.0}%면 매달 **{94만원}**" (+2%p가 15%를 넘으면 ② 대신 "처음 목돈이 {X} 더 있으면 매달 {Y}") |

경계:
- 수익률 0% → (T − P0)/n이다(1억, 2,000만원, 100개월 → 80만원).
- 음수 수익률 → 식은 그대로 쓴다(f < 1, 분모 (f−1)/i는 양수).
- 기간 100년 초과 → 오류 문구.
- 목표 ≤ 지금 목돈이고 수익률 ≥ 0 → '필요 없음'.

### 2-3. 처음 목돈 (ask='initial')

입력: 목표, 매달, 수익률, 기간.

| 경우 | 결과 문장 |
|---|---|
| 필요 | 큰 글자 **"처음에 {9,973만원}이 있으면 돼요"**<br>"매달 {150만원}씩 {20}년 넣으면 {10억 1만원}이 돼요." (+ "지금 모아 둔 돈 {1억원}이면 이미 충분해요." 또는 "지금 모아 둔 돈보다 {X} 더 필요해요.") |
| 필요 없음(P0 ≤ 0) | **"처음 목돈 없이도 돼요"**<br>"매달 {200만원}만 {5}년 넣어도 {1억 3,897만원}이 모여요." |
| 기간 0 | "지금 {목표}이 있어야 해요." (P0 = T) |
| 대안 2개 | ① "매달 {160만원}(+10만원)이면 처음 **{8,559만원}**" ② "기간을 {25}년으로 늘리면 **처음 목돈 없이도 돼요**"(0 이하일 때) 또는 "…처음 **{X}**" |

경계: 수익률 0% → T − C·n이다(1억, 50만원, 120개월 → 4,000만원). 음수 수익률은 식 그대로 쓴다.

### 2-4. 필요한 수익률 (ask='rate')

입력: 목표, 지금 목돈, 매달, 기간.

| 경우 | 결과 문장 |
|---|---|
| 0% 초과 ~ 15% | 큰 글자 **"연 {6.0}% 수익률이면 돼요"**<br>"{20}년 동안 매달 {150만원}씩 넣으면 {10억 87만원}이 모여요." |
| 15% 초과 ~ 30% | 같은 문장 + 알약 **"! 높은 수익률"** + "연 15%가 넘는 수익률을 오래 내기는 어려워요." + 대안 2개 |
| 30% 초과 또는 100%로도 못 닿음 | **"수익률만으로는 어려워요"** + 대안 2개 |
| 0% 이하로도 닿음 | **"수익률이 연 {−2.4}%여도 닿아요"**<br>"넣는 돈만 {5,400만원}으로 목표 {5,000만원}보다 많아요." |
| −50%로도 닿음 | **"수익률과 상관없이 닿아요"** |
| 기간 0 | "기간이 0년이면 불릴 시간이 없어요. 기간을 넣어 주세요." (P0 ≥ T이면 "지금 바로 닿아요") |
| 대안 2개 | ① "연 7%로 잡으면 **{21년 5개월}** 걸려요" ② "연 7%로 {10}년 안에 닿으려면 매달 **{470만원}**" |

경계:
- 목표 ≤ 지금 목돈이고 매달 0원 → 음수 수익률로 답한다(5,000만원, 6,000만원 → −3.6%).
- 기간 100년 초과 → 오류.
- 버튼 [연 {r}% 내는 투자 규칙 찾기 →]: r ≤ 0이면 숨기고, r > 30%이면 비활성으로 두고 "너무 높아 찾기 어려워요" 툴팁을 단다.

## 3. ① 돈의 가치 저울 — 화면 문구 전부

- 카드 제목: **돈의 가치 저울** + 도움말 버튼 `?`
- 부제(캡션): "물가가 오르면 같은 돈으로 살 수 있는 게 줄어요. 양쪽이 같은 가치가 되게 맞춰 드려요."
- 왼쪽 접시 라벨: **오늘 돈** / 금액: fmtKRW 큰 글자(누르면 입력칸, `data-money`). aria-label "오늘 돈 고치기"
- 오른쪽 접시 라벨: **{2046}년 통장 숫자** / 금액 같은 방식. aria-label "{2046}년 통장 숫자 고치기"
- 받침 입력: **기간** `[20]년`(정수 0 ~ 100) · **물가** `연 [2.5]%`(−2 ~ 10, plan.inflation과 같은 값)
- 같은 가치 문장(aria-live="polite")
  - 보통: "오늘 **{1억원}**과 {2046}년 통장에 찍힐 **{1억 6,386만원}**은 같은 가치예요."
  - 기간 0: "같은 해라 금액도 같아요."
  - 물가 0: "물가가 그대로면 금액도 그대로예요."
  - 물가 음수: "물가가 내리면 그해 숫자가 더 작아도 같은 가치예요."
- 기본 버튼: **[이 금액을 목표로 ▶]** — ②의 목표에 round(그해 숫자)를, 기간에 years를 넣고 fromScale을 남긴다. ②가 '기간' 질문이면 목표만 넣는다.
- 보조 텍스트 버튼: **[계획 숫자 불러오기]** — 목표 모드는 then=goalAmount, years=goalYears이고, 노후 모드는 then=필요 자금, years=은퇴까지이며, 둘 다 last='then'이다.
- 토스트: "실행 목표에 {1억 6,386만원}, {20}년을 넣었어요." [되돌리기]
- `?` 팝오버: "왼쪽은 오늘 물가로 본 돈, 오른쪽은 그해 통장에 실제로 찍힐 숫자예요. 물가가 해마다 {2.5}%씩 오르면 {20}년 뒤엔 {1억 6,386만원}이 있어야 오늘 {1억원}만큼 살 수 있어요. 예) 오늘 1만원짜리 국밥 → {2046}년 {16,386원}."
- 입력 오류: "기간은 0~100년으로 넣어 주세요." / "물가는 −2%에서 10% 사이로 넣어 주세요."
- 동작: 고친 접시 쪽을 기준으로 금액이 커지면 그쪽이 내려가고 작아지면 올라가게 3° 기울인다. 0.25초 뒤 수평으로 돌아온다. `prefers-reduced-motion`이면 움직이지 않는다. 기간이나 물가를 고치면 `last` 쪽 금액을 고정하고 반대쪽을 다시 계산한다.
- 레이아웃: 1280px 이상이면 ①:② = 5:7로 나란히, 그보다 좁으면 위아래로 쌓는다. 휴대폰에서 ② 입력칸은 2열이다.

```js
plan.calc  = { ask: 'monthly',            // 'years'|'monthly'|'initial'|'rate'
               target, initial, monthly, rate /*% 숫자*/, years /*정수*/,
               link: null|'plan',          // 노후 모드: 필요 자금을 따라감
               fromScale: null|{ today, years } }  // 저울에서 가져온 표시(목표를 직접 고치면 null)
plan.scale = { today, then, years, last: 'today'|'then' } // 물가는 plan.inflation
```
- 계산은 core/plan.js에 순수 함수로 둔다: `scaleThen`, `scaleToday`, `requiredInitial`, `solveCalc(calc, inflPct) → {status, value, shown, fv, invested, gain, real?, alts:[{label, apply}]}`. 그리고 `requiredRate`에 `lo` 옵션을 더한다.
- 결과(답)는 저장하지 않는다. 열 때마다 계산한다.

### 5-2. 예전 데이터 채우기 — `migratePlan(p)` (initPlan, 기록 되돌리기, 새 계획 복사 때 모두 거침)

1. `p.goalBasis === 'today'`이면 `p.goalAmount = Math.round(goalAmount × (1+inflation/100)^(round(goalYears×12)/12))`로 바꾼다. 그다음 `delete p.goalBasis`.
2. `delete p.showToday`.
3. calc가 없을 때
   - 목표 모드: `{ask:'monthly', target: goalAmount, years: goalYears, initial, monthly, rate: singleRate(p), link:null}`
   - 노후 모드: `{ask:'monthly', target:null, years: retireAge−age, initial, monthly, rate: singleRate(p), link:'plan'}` (target은 첫 compute 뒤 round(needAtRetire)로 채운다)
   - `singleRate`: 구간이 하나면 그 값. 아니면 `equivalentSingleRate`(적립 개월 수, 목돈·증가 없이)를 0.1 단위로 반올림한다.
4. scale이 없을 때: 목표 모드는 `{then: goalAmount, years: goalYears, last:'then'}`, 노후 모드는 첫 compute 뒤 `{then: round(needAtRetire), years: retireAge−age, last:'then'}`. 계산에 실패하면 `{today: 1억, years: 20, last:'today'}`.
5. INPUT_KEYS에서 'goalBasis'를 뺀다. calc·scale은 넣지 않는다.
6. 엔진 computeGoal의 goalBasis 분기는 남겨 둔다(하위 호환, 테스트 영향 없음). UI만 더는 쓰지 않는다.
7. `newPlan()`: goalBasis·showToday를 빼고 calc·scale 기본값을 넣는다. '지금 계획 가져오기' 복사에는 calc의 initial·monthly·rate도 함께 넣는다.
