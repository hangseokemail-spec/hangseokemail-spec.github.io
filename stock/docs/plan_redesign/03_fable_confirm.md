## 2. GPT 시안

### 채택
- 5:7 두 카드, 질문 칩 네 개와 같은 높이의 '?' 칸, 결과 상자 안의 큰 답 + 막대.
- 저울 그림(scale.svg)의 선 굵기와 색 토큰, 3.5° 기울었다 250ms 안에 돌아오는 움직임, 동작 줄이기 대응.
- 금액 입력 밑 한글 읽기(1억 6,386만원), 조작 영역 44px, aria-pressed, 포커스 링.
- 손실일 때 '줄어든 돈'(파랑), 넣은 돈 전체를 기준으로 나누는 방식.
- 휴대폰: 저울 → 실행 목표 순서로 쌓기, 질문 칩 2×2, 입력 2열, 버튼 세로.

### 바꿀 것
1. **금액 입력을 접시 위에 올린다.** 시안은 입력 두 칸이 카드 가운데에 붙어 있고 접시는 비어 있어, 저울이 장식으로 보인다. 사용자 말은 "저울 위에 올리고"다.
   - 방법: 저울 그림을 카드 너비 전체로 넓히고, 입력 두 칸을 접시 중심(그림 너비의 1/6, 5/6 지점)에 맞춘 2열로 놓는다. 입력 상자 아랫변이 접시 윗선에 닿게 한다(간격 0~4px). 라벨(오늘 돈 / 2046년 통장 숫자)은 입력 위, 한글 읽기는 접시 아래.
   - 기울 때 입력 상자도 접시와 같은 translateY로 함께 움직인다. 그래야 돈이 올라가 있는 것으로 읽힌다.
   - 휴대폰(390px)에서도 2열을 유지한다. 칸 너비가 150px 안팎이라 163,860,000원이 들어간다. 12자리 넘는 금액은 글자를 한 단계 줄인다.
2. **기간·물가는 받침 바로 아래 가운데, 두 접시 사이.** 시안 위치를 유지하되 가운데 정렬을 받침 꼭짓점에 정확히 맞춘다(시안은 왼쪽으로 조금 치우쳤다). 라벨은 "기간" / "물가(연)". 받침 색(--bg-selected)을 입력 둘의 배경 띠로 이어 받침의 일부로 보이게 한다. 접시와 같은 줄에 두지 않는다(금액 넷이 한 줄에 서면 다시 복잡하다).
3. **같은 가치 문장은 ≈ 기호를 쓰지 않는다.** ≈는 "대충 비슷하다"로 읽혀 저울의 뜻을 약하게 만든다. 만원 단위 반올림은 표시 문제일 뿐 두 금액은 정의상 같은 가치다. 문장은 말로 쓰고("…같은 가치예요"), 기호가 필요하면 가로대 가운데 고리에 '=' 하나만 둔다.
4. **'저울 움직여 보기' 버튼은 뺀다.** 시연용이고, 금액을 고치면 어차피 움직인다. 그 자리에는 텍스트 버튼 [계획 숫자 불러오기]를 둔다.
5. **결과 막대 색: 불어난 돈 = --up(빨강) 유지.** 한국 주식 화면 관례와 앱의 다른 화면과 같다. 대신 두 가지를 고친다.
   - 경고 상자(수익률만으로는 어렵다)가 같은 빨강 계열이라 '이익'과 '경고'가 한 화면에서 같은 색이 된다. 경고는 --warn(주황·호박색) 계열 바탕 + '!' 표시로 바꾼다.
   - 색만으로 구분하지 않게 막대 아래 라벨(넣은 돈 / 불어난 돈)은 지금처럼 늘 글자로 둔다. 넣은 돈은 회색 유지.
6. **답 표기:** "12년 0개월" → "12년"(0개월은 생략), "연 60.81%" → 0.1%p 올림 "연 60.9%". 결과 상자의 작은 제목 "기간 결과"는 빼고 큰 답이 문장이 되게 한다("12년 걸려요").
7. **대안 기준 수익률은 연 7%로 통일**(시안 6%, 구현 7%, 새 계획 기본값 7%).
8. **'이 금액을 목표로'를 '기간' 질문 상태에서 눌렀을 때:** 시안은 필요 수익률로, 구현은 매달 넣을 돈으로 질문을 바꾼다. 둘 다 사용자가 고른 질문을 말없이 바꾼다. 질문은 그대로 두고 목표만 넣는다. 저울의 기간은 fromScale에 남겨 '오늘 돈 가치를 지키려면' 줄에 쓴다.
9. **휴대폰:** 결과 상자가 입력 네 칸 아래로 밀려 답을 보려면 스크롤해야 한다. 입력을 고칠 때 결과 상자가 화면 밖이면 답 한 줄("12년 걸려요")을 화면 아래에 3초간 띄우는 대신, 더 간단하게 결과 상자를 질문 칩 바로 아래(입력 위)로 올린다. 넓은 화면은 시안 순서 그대로.

## 3. 구현 초안(goalcards.js·goalcalc.js)과 어긋나는 점

### 필수
1. **올림이 없다(결정 8).** `매달 ${fmtKRW(a.value)}`는 반올림, 수익률은 toFixed(2). 질문을 바꿀 때와 [계획 바꾸기]에도 올리지 않은 값이 들어간다. → goalcalc.solve 안에서 금액은 10만원 이상 1만원 단위(미만 1천원 단위), 수익률은 0.1%p로 올린 뒤 full·end·paid를 그 값으로 다시 계산해 돌려준다. 화면·막대·반영이 모두 그 값을 쓴다.
2. **음수 수익률 답이 잘못 나온다.** solveRate의 'zero'는 −50%로도 닿을 때만 나오고 value가 늘 −0.5다. 그래서 (a) −2.4%처럼 0 이하인 보통 답은 'ok'로 떨어져 "이 수익률을 꾸준히 내면"이라고 나오고, (b) 'zero'일 때는 full.rate=−50%로 막대를 그리고 [계획 바꾸기]가 −50%를 계획에 넣는다. → 상태를 셋으로: value ≤ 0이면 'nonpos'("수익률이 연 −2.4%여도 닿아요"), −50%로도 닿으면 'any'("수익률과 상관없이 닿아요", 막대 없음, 수익률은 반영하지 않음).
3. **저울의 그해 금액을 `S._then`에 둔다.** 저장 대상 객체에 임시 값이 섞이고, 다시 열면 last='then'인데 _then이 없어 오늘 쪽이 고정된다. → scale을 `{today, then, years, last}`로 저장하고 _then을 없앤다.
4. **ensureCards의 채우기.** (a) 수익률이 첫 구간 값이다 → equivalentSingleRate(결정 5). (b) scale을 today로 반올림해 저장해서 10억 목표가 저울에서 999,999,999원대로 보일 수 있다 → then=goalAmount, last='then'으로 채운다. (c) goalBasis='today' 변환(결정 6)이 없다.
5. **범위·오류 처리.** 저울 기간 0~80(확정 0~100), 물가 −5~20(확정 −2~10). 범위를 넘으면 말없이 잘라 버린다 → aria-invalid + 안내 문구. 목표 0원이면 '기간' 질문이 "지금 바로"라고 답한다 → "목표 금액을 넣어 주세요."
6. **'이 금액을 목표로'가 질문을 바꾼다**(years → monthly). → 2절 8번대로 질문 유지, fromScale 저장, 실질 목표 줄 추가(결정 3).
7. **30% 넘는 답에도 [계획 바꾸기]·[투자 규칙 찾기]가 켜져 있다**('hard'일 때 ok=true). → 30% 초과는 둘 다 끄고 대안 칩만 남긴다. 15~30%는 켜 두되 경고를 보인다.
8. **기간 칸에 소수가 들어간다.** 대안 칩과 질문 전환이 `(months/12).toFixed(1)`을 넣어 "10.8년"이 보인다. → 기간 입력은 정수 년. 개월 답을 칸으로 옮길 때는 ⌈n/12⌉년으로 넣고 "넉넉하게 13년으로 넣었어요"를 한 번 알린다.
9. **대안 칩을 누르면 질문이 바뀐다**(매달 질문에서 '기간 늘리면' 칩 → 기간 질문으로). → 질문은 그대로 두고 바뀐 칸(기간·수익률 등)만 고친다.
10. **노후 모드 연결(결정 9), 반영 뒤 [되돌리기] 토스트**는 hooks 쪽에 있어야 하는데 goalcards.js에서 확인되지 않는다. plan.js 연결부에서 반드시 넣는다.

### 있으면 좋음
- 접시 위 입력 배치(2절 1번)는 디자인 필수지만 CSS·마크업 작업이라 계산 수정과 나눠서 한다.
- 닿을 때의 '다른 길' 2개(매달 +10만원 / 연 +2%p)가 기간 질문에 없다. 지금은 못 닿을 때만 나온다.
- 조건부 캡션("아래 계획의 목돈 N건은 넣지 않았어요" 등), "아래 계획과 달라요" 표시, [내 자산에서] 링크.
- 처음 목돈 답 옆 "지금 모아 둔 돈보다 X 더 필요해요", 매달 답 옆 "지금 계획보다 X 더예요".
- 저울 경계 문장(기간 0, 물가 0, 물가 음수), '?' 도움말(국밥).
- 기울기 방향을 '금액이 커지면 내려감'으로(지금은 고친 쪽이 늘 내려감). 지금 방식도 "올려놓았다"로 읽혀 틀리지 않다.
- `void el; void fv;`와 쓰지 않는 import 정리. 문장 안 조사(과/와, 이/가)는 금액이 늘 '원'으로 끝나 지금은 맞다.

## 4. 최종 화면 문구 확정본

### ① 돈의 가치 저울
- 제목: **돈의 가치 저울** `?`
- 부제: 오늘과 같은 만큼 사려면 그해에 얼마가 필요할까요?
- 왼쪽 접시 라벨: **오늘 돈** / 오른쪽 접시 라벨: **{2046}년 통장 숫자**
- 받침 라벨: **기간** `[20] 년` · **물가(연)** `[2.5] %`
- 같은 가치 문장: 오늘 **{1억원}**과 {2046}년 통장의 **{1억 6,386만원}**은 같은 가치예요.
  - 기간 0: 같은 해라 금액도 같아요.
  - 물가 0: 물가가 그대로면 금액도 그대로예요.
  - 물가 음수: 물가가 내리면 그해 숫자가 더 작아도 같은 가치예요.
- 버튼: **[이 금액을 목표로]** (기본) · [계획 숫자 불러오기] (텍스트)
- 알림: 실행 목표에 {1억 6,386만원}, {20}년을 넣었어요. [되돌리기]
- 오류: 기간은 0~100년으로 넣어 주세요. / 물가는 −2%에서 10% 사이로 넣어 주세요.
- 도움말(?): 왼쪽은 오늘 물가로 본 돈, 오른쪽은 그해 통장에 실제로 찍힐 숫자예요. 물가가 해마다 {2.5}%씩 오르면 {20}년 뒤엔 {1억 6,386만원}이 있어야 오늘 {1억원}만큼 살 수 있어요. 예) 오늘 1만원짜리 국밥 → {2046}년 {16,386원}.

### ② 실행 목표 만들기
- 제목: **실행 목표 만들기**
- 질문 줄: **무엇이 궁금해요?**
- 질문 칩 4개: **걸리는 기간** / **매달 넣을 돈** / **처음 목돈** / **필요한 수익률**
- 입력 라벨: **목표 금액** (캡션: 그해 통장에 찍힐 금액) · **지금 목돈** · **매달 넣을 돈** · **연 수익률** · **기간**. 고른 질문의 칸은 `?`.
  - 노후 모드: 목표 금액 → **은퇴 때 필요 자금**(캡션: 아래 계획에서 계산 · 고치면 연결이 풀려요 [다시 가져오기]), 기간 → **은퇴까지**({60}세)
- 늘 보이는 캡션: 수익률 한 가지, 매달 같은 금액을 월말에 넣는다고 보고 계산해요.

결과 문장 형식(큰 글자 / 작은 글자):

| 질문 | 경우 | 큰 글자 | 작은 글자 |
|---|---|---|---|
| 걸리는 기간 | 닿음 | **{12년} 걸려요** | {2038년 11월}에 {1억 6,434만원}이 모여 목표를 넘어요. |
| | 저울에서 온 목표 | (한 줄 더) | 오늘 돈 {1억원} 가치를 지키려면 {9년 5개월}이면 돼요. [이 목표로 바꾸기] |
| | 이미 넘음 | **지금 바로 닿아요** | 지금 목돈이 목표보다 {1,000만원} 많아요. |
